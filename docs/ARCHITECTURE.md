# Архитектура

## Слои

1. `api/routes` — REST API для внешних интеграций.
2. `web/router.py` — браузерная панель для менеджеров.
3. `services` — бизнес-логика: ценообразование, импорт, отчёты, уведомления.
4. `repositories` — доступ к данным.
5. `models` — SQLAlchemy модели.
6. `worker` — фоновые задачи Celery.

## Поток автоцены

1. Товар берётся из БД.
2. `KaspiClient` получает список предложений конкурентов.
3. `PricingEngine` фильтрует продавцов, применяет стратегию и лимиты.
4. Если изменение безопасное — новая цена отправляется в Kaspi.
5. В БД пишется `PriceHistory` и создаётся `Alert`.

## Почему так

- Реальный Kaspi API может измениться, поэтому он изолирован в отдельном адаптере.
- Pricing engine не зависит от FastAPI, поэтому его легко тестировать.
- Celery можно масштабировать отдельно от web-сервера.
- PostgreSQL подходит для продакшена, SQLite — для локальной разработки.
