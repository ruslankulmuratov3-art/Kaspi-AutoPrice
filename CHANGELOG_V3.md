# Kaspi AutoPrice v3 — изменения

## Найденные первопричины

1. Долгий автопилот выполнялся внутри web-процесса и терял состояние после restart.
2. Одновременно могли стартовать локальный и Render-процессы.
3. Ошибки 405/429 повторялись для сотен товаров вместо общего cooldown.
4. Кэш конкурентов был привязан только к времени товара и не имел состояния источника.
5. XML мог сохраняться после частичной обработки выбранного набора.
6. XML-хранилище опиралось на локальные файлы и большие JSON-записи в общей таблице логов.
7. Запрос Kaspi к XML мог запускать тяжёлую пересборку.
8. `/products/import` ошибочно воспринимался как подтверждённый прямой API цены.
9. Лимит изменений не имел отдельной очереди и транзакционной блокировки.
10. История не разделяла подготовленную XML-цену и подтверждённое применение.

## Основные исправления

- DB-backed `AutopilotJob` с heartbeat, stop, resume и cursor.
- `CompetitorSnapshot` и `CompetitorSourceState` с circuit breaker/cooldown.
- `XmlFeedVersion` и `XmlFeedPull` в PostgreSQL.
- Проверка полного XML перед атомарной активацией.
- `PriceChangeEvent` и `PendingPriceChange` для лимита и очереди.
- Публичный XML отдаётся мгновенно и не запускает расчёт.
- Прямой API цены выключен до появления официального endpoint.
- Новый компактный UI, анимации, polling статуса, мобильный drawer.
- Тесты для цен, XML, поиска, 429/circuit breaker и отключённого direct API.

- Добавлены `autopilot_job_items`: pause/resume и restart сохраняют рассчитанные решения по каждому товару.
